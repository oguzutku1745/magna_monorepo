# Aztec 5.1 Inbox feasibility evidence — 2026-08-23

Result: **PASS for Gate A's canonical Inbox serialization, immutable-sender binding, and private-consumption mechanics**.

This was not a TXE test. The reproducible run used the official Aztec `5.1.0` local network, its deployed canonical L1 Inbox, real Solidity transactions, normal proposer synchronization, a deployed Noir contract, client-side ClientIVC proofs, and protocol nullification. Magna's API was not involved.

## Negative and replay evidence

- Direct non-portal message: rejected with `No L1 to L2 message found`.
- Content changed from `0x4242` to `0x4243`: rejected with `No L1 to L2 message found`.
- Message secret changed to `0x1`: rejected with `No L1 to L2 message found`.
- Exact portal message: generated a ClientIVC proof and reached `proven / success` at L2 block `10`.
- Exact replay: rejected with `No non-nullified L1 to L2 message found` for the consumed portal leaf.
- Duplicate L1 authorization: portal reverted with `authorization already accepted`.

The successful transaction emitted protocol nullifiers. The CLI labels their types as unknown, so this evidence does not guess which receipt position is the message nullifier; the exact replay failure proves that the canonical message is nullified.
